# Архитектура Biblia App

## Основной принцип

Персональный конструктор — не отдельное шестое приложение. Это способ собрать
собственную композицию из того же набора функций, на котором построены готовые
приложения.

```text
                       Bible Desktop API
                              │
                         API boundary
                              │
                       Feature Registry
                      ╱                 ╲
             готовые композиции     личная композиция
          Библия / Иконы / ...     выбранные пользователем
                      ╲                 ╱
                         единый App Shell
```

Новая функция сначала регистрируется как feature. После этого она может быть
добавлена в готовое приложение, показана отдельно и разрешена в конструкторе —
без отдельного механизма интеграции.

## Слои

### Bible Desktop API

`https://bible-desktop.com/api` остаётся единственным backend и источником
данных. Нужные расширения вносятся обратно совместимо в Bible Desktop, а не
реализуются вторым backend внутри Biblia App.

### API boundary

`src/services/api` содержит transport, контракты и нормализацию ответов. Vue-
компоненты не собирают URL вручную и не знают о формате envelope API.

### Feature Registry

Каждая запись в `src/registry/features.ts` определяет:

- стабильный `id` и группу;
- RU/DE-название и описание;
- маршрут и иконку;
- доступность (`available` или `planned`);
- зависимости от других features;
- видимость в конструкторе, навигации и standalone-режиме;
- API-возможности и, при наличии, ключ статистики главной.

`resolveFeatureSelection` добавляет необходимые зависимости. Planned-функция не
попадает в пользовательскую конфигурацию до её фактической готовности. Удаление
базовой функции также удаляет зависимые от неё функции.

### Готовые приложения

`readyApps` — официальные композиции тех же feature IDs. В foundation доступны
Писание, Молитвослов, Православный календарь, Календарь икон и
Церковнославянский. Это не отдельные кодовые базы и не внешние ссылки.

### Персональное приложение

Конфигурация версии 3 хранит locale, ordered sections/navigation, стартовую
функцию и timestamps. При создании она сохраняется через profile API Bible
Desktop. Браузер локально хранит только идентификатор профиля, secret и код
восстановления; secret не помещается в URL.

## Домены и локализация

Язык по умолчанию выбирается на старте:

1. ранее сохранённый ручной выбор;
2. немецкий для `biblia-app.de` и его поддоменов;
3. русский для `biblia-app.ru`, localhost и остальных hostnames.

Одна сборка обслуживает оба домена. Все пользовательские строки проходят через
словарь `src/i18n/messages.ts`; названия контента приходят из API.

## PWA и данные

Service worker кеширует App Shell и только явно перечисленные публичные GET-
эндпоинты. Profile API, переводчик и OCR не кешируются. Это исключает сохранение
секретных заголовков и персональных ответов в общем runtime-cache.

Offline-режим foundation гарантирует запуск оболочки и ранее полученные
публичные списки. Полноценная офлайн-Библия требует отдельного этапа с контролем
объёма и версии данных.

## Безопасность

- production API base задаётся публичной переменной `VITE_API_BASE_URL`;
- frontend не содержит backend/API secrets;
- translator/OCR получают случайный installation UUID, но не обходят лимиты;
- удалённые профили читаются только с `X-Profile-Secret`;
- profile secret не логируется, не кешируется service worker и не включается в
  ссылку восстановления;
- `.htaccess` добавляет основные security headers и SPA fallback.

## Правило расширения

Для новой возможности нужно:

1. подтвердить или добавить обратно совместимый endpoint в Bible Desktop;
2. добавить контракт и метод в `src/services/api`;
3. зарегистрировать feature и зависимости;
4. подключить экран/маршрут;
5. при необходимости включить feature в готовую композицию;
6. добавить тест реестра или поведения и обновить API-карту.
