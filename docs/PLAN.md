# План развития

План разбит на небольшие проверяемые этапы. Foundation создаёт архитектурное
сердце платформы, но не объявляет все глубокие сценарии готовыми.

## Этап 1 — Foundation

Статус: реализован и отправлен в `main`; production deployment не выполнен.

- независимый Vue 3 / TypeScript / Vite / PWA проект;
- App Shell и адаптивная навигация;
- Feature Registry и resolver зависимостей;
- готовые композиции и персональный конструктор;
- RU/DE по домену с ручным переключателем;
- profile create/recover и локальное хранение credentials;
- обзорные экраны на production API для основных разделов;
- документация архитектуры, API и миграции.

## Этап 2 — Полное чтение Библии

Статус: базовый reader flow реализован локально; закладки и расширенное
сохранение состояния остаются отдельным блоком.

- выбор перевода, книги и главы, прямые ссылки на стих;
- безопасный рендер `plain_text`, изменение размера, переходы по главам;
- поиск по тексту/ссылке и переход к найденному стиху;
- Strong и параллельные места по выбранному стиху;
- следующая задача: закладки, локальная история и обработка нумерации при
  календарных ссылках.

## Этап 3 — Календарь, молитва и богослужение

- детальный день с иконами и полными чтениями;
- календарная служба и связанные литургические тексты;
- просмотр произведения/редакции и молитвенных разделов;
- сохранение избранного и последней позиции.

## Этап 4 — Персональное приложение

- редактирование порядка и состава после создания;
- синхронизация обновлений с revision control profile API;
- экспорт, удаление и управление устройствами;
- install prompt и проверенный offline restart;
- понятный конфликтный flow для двух устройств.

## Этап 5 — Церковнославянское обучение

- алфавит, цифирь и справочные материалы;
- упражнения и повторение;
- прогресс как отдельный profile module;
- включение `slavonic.learning` в конструктор только после готовности.

## Этап 6 — Production rollout

- Plesk document root для общей `dist`-сборки;
- DNS/HTTPS для `biblia-app.ru` и `biblia-app.de`;
- smoke tests обоих доменов и прямых маршрутов;
- проверка service worker/update flow;
- accessibility и performance audit release build;
- наблюдение за API errors и лимитами без сбора лишних персональных данных.

## Критерий для каждого следующего feature

Feature считается готовой, когда существует реальный API/data flow, экран с
loading/error/empty states, RU/DE-интерфейс, релевантный тест, production build и
обновлённая документация. Planned-запись в Registry готовой функцией не является.
