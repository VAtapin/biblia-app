# Состояние проекта Biblia App

## Реализовано

- Создан независимый Vue 3 / TypeScript / Vite / PWA frontend.
- Реализованы App Shell, адаптивная навигация и RU/DE-интерфейс с выбором языка
  по домену и сохранением ручного выбора.
- Feature Registry стал единым источником готовых приложений и персонального
  конструктора; зависимости и planned-функции обрабатываются автоматически.
- Подключены production-данные Bible Desktop для главной, переводов Библии,
  молитвенной библиотеки, календаря, икон и публичных материалов.
- Реализовано чтение Библии: перевод → книга → глава → стих, прямые ссылки,
  изменение размера текста, поиск, Strong и параллельные места.
- На узких экранах сведения о стихе открываются во всплывающем окне, а номера
  стихов расположены рядом с текстом без постоянной пустой колонки.
- Персональный экран устойчив к сохранённым профилям, у которых есть `sections`,
  но нет более нового поля `navigation`.
- Подключены реальные translator/OCR endpoints и удалённые персональные профили
  с созданием и восстановлением.
- Добавлены архитектурная документация, API-карта, поэтапный план и правила
  выборочного переноса наработок из `my_bible_app`.

## Текущее состояние

- Foundation и базовый reader flow готовы локально; полный `npm run check`
  проходит после добавления reader.
- Источником данных является production API Bible Desktop; отдельного backend в
  этом репозитории нет.
- Закладки, история чтения, офлайн-загрузка целой Библии и связывание календарных
  чтений с конкретными стихами остаются следующим этапам.
- Выбор стиха больше не перезагружает главу: меняется hash и отдельно
  запрашиваются данные Strong/параллельных мест без прокрутки маршрутизатора.
- Production deployment и настройки Plesk из этой среды не проверены.
- Попытка `git pull` в Plesk `httpdocs` не сработала, потому что этот каталог не
  является Git checkout. Публикация выполняется из временного clone.

## Важные решения

- `biblia-app.ru` использует русский язык по умолчанию, `biblia-app.de` — немецкий.
- Готовые приложения являются официальными композициями Feature Registry.
- Персональное приложение является пользовательской композицией тех же features.
- Старый frontend Bible Desktop не переносится; API можно расширять обратно совместимо.
- `my_bible_app` используется как источник проверенных наработок, но не копируется целиком.
- Service worker кеширует только явно разрешённые публичные GET; профили, OCR и
  переводчик не попадают в runtime-cache.
- Оба домена используют одну сборку; `georg-kloster.de` исключён из проекта.
- Владелец выбрал каталог публикации
  `/var/www/vhosts/biblia-app.ru/httpdocs/dist`; постоянный checkout `app`
  не требуется. Настройки Document Root не изменять без согласования.

## Известные проблемы

- DNS/HTTPS, общий Plesk document root и smoke tests двух production-доменов ещё
  не настроены и не проверены.
- Если старый checkout `app` был создан на сервере, его содержимое и удаление
  ещё не проверены.
- Библиотека пока представлена обзорными списками; просмотр произведений и
  молитвенных разделов входит в следующий этап.

## Рекомендуется следующим

- Углубить календарь и богослужебную библиотеку, затем добавить закладки и
  историю чтения.
- Опубликовать сборку в `httpdocs/dist`, проверить фактический Document Root и
  оба домена. Удалить прежний `app` только после проверки его содержимого.

## Проверки

- `npm run check` — успешно: TypeScript, 14 unit-тестов и production PWA build.
- В браузере на live production API проверены главная, календарь (включая прямую
  ссылку на дату), каталог икон, молитвенная библиотека, переводы и RU/DE UI.
- Новый reader проверен в браузере на русской и немецкой главах, прямой ссылке
  на стих, поиске, Strong и параллельных местах.
- Журнал браузера выявил прежнюю ошибку PersonalAppView на профиле без поля
  `navigation`; добавлен fallback и unit-тест. Реальный приватный профиль повторно
  не открывался для проверки.
- Mobile viewport 390×844: горизонтального overflow на главной и в конструкторе
  нет; reader и каталог книг также проверены без overflow. Открытие и закрытие
  окна стиха, переход между стихами без повторной загрузки главы, а также
  прежняя боковая панель на ПК проверены в браузере; ошибок консоли нет.
