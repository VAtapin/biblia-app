# Biblia App

Новая веб-платформа, в которой готовые православные приложения и персональная
сборка создаются из одного реестра функций. Пользователь может сразу открыть
Библию, молитвослов, календарь, иконы или церковнославянские инструменты либо
собрать собственную навигацию из тех же модулей.

Данные и прикладная логика не дублируются: frontend использует production API
[Bible Desktop](https://bible-desktop.com/api). Существующий Bible Desktop
продолжает работать как отдельный продукт и единый backend.

## Домены и язык

- `biblia-app.ru` — русский интерфейс по умолчанию;
- `biblia-app.de` — немецкий интерфейс по умолчанию;
- ручной выбор RU/DE сохраняется локально и имеет приоритет над доменом;
- `georg-kloster.de` в проект не входит.

Оба домена должны указывать на одну production-сборку. Разница определяется по
`window.location.hostname`, отдельные сборки не требуются.

## Что входит в foundation

- единый App Shell с адаптивной desktop/mobile-навигацией;
- Feature Registry как источник готовых приложений и конструктора;
- конструктор с зависимостями модулей, быстрым стартом и восстановлением;
- удалённый профиль без учётной записи, секрет хранится только на устройстве;
- живые экраны переводов Библии, молитвенной библиотеки, календаря и икон;
- чтение книг и глав Библии с прямыми ссылками на стихи, поиском, Strong и
  параллельными местами;
- переводчик и распознавание надписей через публичный внешний режим API;
- вопросы веры, рецепты, тесты, туры 360° и полезные материалы;
- RU/DE-интерфейс, PWA-манифест и безопасное кеширование только публичных GET;
- Apache/Plesk fallback для прямых SPA-маршрутов.

Foundation не пытается за один шаг воспроизвести все глубокие сценарии Bible
Desktop. Например, закладки и офлайн-загрузка целой Библии ещё не реализованы.
Следующие продуктовые этапы описаны в [плане](docs/PLAN.md).

## Локальная разработка

Требуется Node.js 22 или новее.

```bash
npm ci
npm run dev
```

Проверка проекта:

```bash
npm run check
```

Команда выполняет проверку TypeScript, unit-тесты и production build. Результат
сборки находится в `dist/`.

Если API будет перенесён, создайте локальный `.env` на основе `.env.example`.
Секреты и API-ключи frontend не требуются и не должны попадать в сборку.

## Структура

```text
src/app/           маршруты и общий App Shell
src/apps/          экраны готовых приложений
src/registry/      определения features и композиция зависимостей
src/personal/      схема персональной конфигурации и локальные credentials
src/services/api/  единственная граница с Bible Desktop API
src/stores/        язык и локальные пользовательские предпочтения
src/views/         главная, конструктор и персональное приложение
docs/              архитектура, API-карта, план и перенос наработок
```

Подробнее: [архитектура](docs/ARCHITECTURE.md), [API-карта](docs/API_CATALOG.md)
и [правила переноса из my_bible_app](docs/MIGRATION_FROM_MY_BIBLE_APP.md).

## Production на Plesk

Принятая схема: репозиторий находится в `/var/www/vhosts/biblia-app.ru/app`, а
document root обоих доменов указывает на
`/var/www/vhosts/biblia-app.ru/app/dist`. `biblia-app.de` подключается к тому же
document root. HTTPS настраивается для обоих доменов. Существующий `httpdocs`
Plesk не удаляется и не превращается в Git-репозиторий.

Первый запуск (только если каталога `app` ещё нет):

```bash
cd /var/www/vhosts/biblia-app.ru && \
test ! -e app && \
git clone --branch main --single-branch https://github.com/VAtapin/biblia-app.git app && \
cd app && \
export PATH="/opt/plesk/node/22/bin:$PATH" && \
npm ci && \
npm run build && \
test -f dist/index.html && \
test -f dist/.htaccess
```

После сборки нужно указать `app/dist` как document root в Plesk для обоих
доменов и проверить HTTPS, главную страницу и прямой SPA-маршрут. Если `app`
уже существует, остановитесь и проверьте его содержимое: не перезаписывайте
действующие файлы.

Обновление уже клонированного проекта:

```bash
cd /var/www/vhosts/biblia-app.ru/app && \
export PATH="/opt/plesk/node/22/bin:$PATH" && \
git pull --ff-only && \
npm ci && \
npm run build && \
test -f dist/index.html && \
test -f dist/.htaccess
```

PHP, Composer и миграции для этого frontend-репозитория не нужны. Изменения API
разворачиваются отдельно из репозитория Bible Desktop.
